Séance 3 · Lab : importer et nettoyer des données

Programmation statistique avec R · Lab 1/3 du projet « Solea » · 2 heures

Compétences visées. À la fin du lab, vous saurez :

  • importer un fichier CSV « à la française » (séparateur ;, virgule décimale, accents) et diagnostiquer un import raté ;
  • réaliser un audit de qualité : doublons, valeurs manquantes, modalités incohérentes, valeurs aberrantes ;
  • nettoyer un jeu de données : texte, dates, valeurs manquantes, aberrations ;
  • documenter vos décisions et exporter un fichier propre.
Mission

Vous venez d’être recruté(e) comme analyste chez Solea, une boutique en ligne (fictive) d’articles de maison, de sport et de beauté. La directrice commerciale vous écrit :

« Voici l’export brut du logiciel de caisse pour l’année 2024. Impossible de l’utiliser tel quel : des collègues l’ont modifié dans Excel, il y a des erreurs de saisie et des trous. Je vous laisse le nettoyer. Dans les prochaines séances, nous en tirerons nos indicateurs et un tableau de bord. Dites-moi ce que vous avez corrigé, et pourquoi. »

Votre livrable : un script de nettoyage reproductible, un fichier ventes_nettoyees.csv et un journal des corrections.

NoteComment travailler pendant un lab
  • Les tâches se font dans l’ordre : chaque tâche modifie l’objet ventes créé à la tâche 1. Si vous êtes perdu(e), ré-exécutez votre code de la tâche 1 (import) puis reprenez.
  • Chaque tâche contient une cellule où écrire votre code, suivie d’une cellule de vérification (libellé vert). Les indices sont repliés : cherchez d’abord ! Les solutions restent verrouillées : elles se débloquent avec le code communiqué en fin de séance.
  • Le bouton Masquer de chaque cellule cache sa sortie une fois lue, pour garder la page lisible.
  • Quand une cellule affiche un data frame (head(ventes), View(ventes)…), le bouton Tableau l’affiche en tableau HTML défilant : pratique pour parcourir 400 lignes.
  • Pour travailler dans RStudio, téléchargez les données : ventes_brutes.csv · ventes_propres.csv (à placer dans le dossier de votre projet).

2. Le lab

Tâche 0 · Explorer le dossier de travail

⏱ 5 min

Vérifiez que les fichiers sont bien là, puis regardez à quoi ressemble le fichier brut avant de l’importer.

Question : quel est le séparateur de colonnes ? Quel est le séparateur décimal ? Que remarquez-vous sur les colonnes categorie et ville ?

NoteRéponse

Séparateur de colonnes : ;. Décimale : , (ex. 29,9). Les colonnes categorie et ville mélangent majuscules, minuscules et parfois des espaces à la fin (Beauté, beaute, PARIS, lyon). Certaines cellules sont vides (;;).

Tâche 1 · Importer le fichier

⏱ 10 min

a) Exécutez d’abord la tentative « naïve » et lisez le message d’erreur :

R s’attend à des colonnes séparées par des virgules : il ne trouve qu’une seule colonne dans l’en-tête (tout est collé, car le séparateur réel est ;), puis des virgules décimales dans les lignes suivantes qu’il prend pour des séparateurs. D’où l’erreur « plus de colonnes que de noms de colonnes ».

b) Importez correctement le fichier dans un objet ventes. Exigences : les nombres à virgule doivent être lus comme des nombres, les cellules vides doivent devenir des NA (y compris dans les colonnes de texte), et l’encodage doit être "UTF-8".

✔ Vérification

AstuceIndice

Le fichier est au format français : pensez à read.csv2(). L’argument na.strings = c("", "NA") dit à R que la chaîne vide est une valeur manquante.

Tâche 2 · Auditer les données

⏱ 15 min

Avant de corriger, mesurez. Explorez ventes (str, summary, head, colSums(is.na(...)), table, unique…) et calculez :

  • n_doublons : le nombre de lignes en double (identiques à une ligne précédente) ;
  • n_cat_brut : le nombre de valeurs distinctes dans categorie (on n’attend que 3 catégories !) ;
  • n_ville_brut : le nombre de valeurs distinctes dans ville ;
  • q_max : la quantité maximale commandée (ignorez les NA).

✔ Vérification

Question : quelles colonnes contiennent des valeurs manquantes, et combien ? Notez-le, vous en aurez besoin pour votre journal de nettoyage.

AstuceIndice

sum(duplicated(ventes)), length(unique(ventes$categorie)), max(ventes$quantite, na.rm = TRUE).

Tâche 3 · Supprimer les doublons

⏱ 5 min

Le logiciel de caisse a parfois enregistré deux fois la même commande. Supprimez les lignes en double de ventes (gardez la première occurrence).

✔ Vérification

AstuceIndice

duplicated() renvoie TRUE pour chaque ligne déjà vue. Gardez les lignes pour lesquelles c’est FALSE : ventes[!duplicated(ventes), ].

Tâche 4 · Harmoniser les textes

⏱ 15 min

categorie et ville contiennent des variantes de la même modalité (PARIS, paris, Paris…). Harmonisez les deux colonnes : espaces supprimés, première lettre en majuscule, le reste en minuscules.

Piège : après la mise en minuscules, regardez table(ventes$categorie). Il reste deux graphies pour la beauté. Corrigez-la : la forme correcte est Beauté.

✔ Vérification

AstuceIndice

Enchaînez trimws(), tolower(), puis paste0(toupper(substr(x, 1, 1)), substring(x, 2)). Pour beaute → beauté, remplacez avec une condition : x[x == "beaute"] <- "beauté" (à faire avant la mise en majuscule).

Tâche 5 · Convertir les dates

⏱ 10 min

La colonne date est du texte au format jj/mm/aaaa. Convertissez-la en vrai type Date. Les commandes sans date ne peuvent pas être placées dans le temps : supprimez-les.

✔ Vérification

AstuceIndice

as.Date(x, format = "%d/%m/%Y"). Une date illisible ou absente devient NA : filtrez avec !is.na().

Tâche 6 · Traiter les valeurs aberrantes

⏱ 10 min

Regardez la distribution de quantite : summary() puis boxplot(). Les quantités de 100 ou 250 sont des erreurs de saisie ; une quantité négative ou nulle n’a pas de sens pour une vente ; une quantité absente est inexploitable.

Règle retenue : supprimer les commandes dont la quantité est manquante, inférieure ou égale à 0, ou supérieure à 20.

Tâche 7 · Traiter les valeurs manquantes

⏱ 10 min

Il reste des NA dans prix_unitaire, remise et mode_paiement. Décisions de l’équipe :

Colonne Décision Justification

remise remplacer par 0 pas de remise renseignée = pas de remise

ImportantÀ retenir
  • Regardez le fichier brut (readLines) avant d’importer ; réglez sep, dec, na.strings, fileEncoding.
  • Auditez avant de corriger : str, summary, colSums(is.na()), duplicated, table.
  • Chaque nettoyage est une décision : documentez-la (ce qui est supprimé, imputé, corrigé, et pourquoi).
  • Un nettoyage se fait dans un script, jamais à la main dans un tableur : il doit être reproductible.
  • Ordre conseillé : doublons → textes → types (dates) → aberrations → manquants.
